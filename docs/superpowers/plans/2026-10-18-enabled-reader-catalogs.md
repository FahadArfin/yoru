# Enabled Reader Catalogs Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Make enabled Suwayomi catalogs browsable and readable across Yoru and Ara Ara while preserving the dedicated MangaDex/Weeb Central integration and adding the three-way integration selector.

**Architecture:** Keep the current core adapters and add a generic extension adapter behind the existing private bridge. Shared identity, destination and preference contracts govern both Node/SQLite and Sites/D1; provider-native records are persisted independently of upstream numeric database IDs. Discovery loads bounded remote pages on demand, and all reading/account/social surfaces use the same resolver and eligibility rules.

**Tech Stack:** JavaScript with JSDoc, React, Express, Hono, Node 22.14+, SQLite, Drizzle/D1, Docker Desktop, Suwayomi, cloudflared, node:test, Playwright.

**Spec:** [Approved design](../specs/2026-10-18-enabled-reader-catalogs-design.md), committed as `e08064c`, approved by the user in this chat. This plan awaits user review and execution-method selection; writing it does not start product implementation.

## Global Constraints

- Work in the existing isolated `yoru-multisource` checkout; confirm its branch and clean/owned changes before execution. Preserve repository/Sites identity and the production URL.
- Keep `mal-anime-*`, `mal-manga-*`, MangaDex UUIDs, `sw-weebcentral-*`, imported chapters, existing data and applied migrations valid. Provider-native IDs never impersonate MAL identities.
- Keep `mangadex` and `weebcentral` as dedicated source IDs; generic source IDs are `suwayomi:<decimal-source-id>`. Source IDs remain strings.
- Modes and labels are exactly `all` / **All sources**, `core` / **MangaDex + Weeb Central**, `extensions` / **Suwayomi extensions**. Default both destinations to `all`.
- Preserve all 21 version-106 provider defaults, account/guest overrides, language grouping and unknown-provider disabled defaults. Global reset restores memberships and both integration modes.
- Preserve both proven adapter paths even for an identical upstream edition. A selected edition never changes merely because an adapter fails or a saved browse mode changes.
- Preserve Yoru's non-explicit policy. Expand Ara Ara to enabled provider-native content behind its existing UI confirmation; do not present that confirmation as API authentication or strong age verification.
- Discover on demand; never crawl every title or download chapters unsolicited. Bound one aggregate request to four source-page operations, two concurrent provider operations and 12 seconds.
- Keep one serialized Suwayomi operation queue shared by core Weeb Central and generic calls initially. Retain the bridge's existing 12 active-request cap.
- Cursors expire after 30 minutes, client cursor length is at most 2 KiB, and server state is at most 1 MiB per continuation session. Reject invalid/expired/selection-mismatched cursors with restart-required state.
- Preserve the 500-page chapter limit, existing image MIME/byte checks, 1 GiB/72-hour image-cache limits and same-origin page delivery. Authoritative identities are never cache-eviction candidates.
- Keep secrets outside Git/output; expose no GraphQL/admin/arbitrary URL/Docker API. Do not bypass source payment, authentication or access challenges.
- Node and Sites must enforce the same contracts, account ownership and destination rules, including before list pagination and image bytes.
- Do not widen anime-specific tools or MAL import/export into accepting provider-native manga. Do not infer MANHWA, popularity or publication dates without supporting metadata.
- Build/recreate only the bridge service during its release; preserve Suwayomi and all volumes. After Ara-native account records exist, version 106 is not a safe rollback target.
- New generic discovery/reading is gated server-side by `READER_EXTENSIONS_ENABLED`, disabled unless exactly `1`. Fixture runtimes explicitly enable it. The compatible rollback build leaves this flag disabled while retaining destination filtering; flags never disable the existing core adapters.

## Review Focus

1. A source integer reused after a Suwayomi restore must not bind an old bookmark to another title/chapter. Pin this in Tasks 2 and 5.
2. A mixed provider, late response or cached cover must not put an Ara-only title into Yoru history, suggestions, rooms or images. Pin this in Tasks 6, 8, 9 and 11.
3. Same-name works, language editions and matching chapter numbers must stay distinct without exact equivalence evidence; an integration switch must not transfer progress. Pin this in Tasks 1, 5 and 12.
4. Failed sources, filtered-empty pages and cursor expiry must not starve later enabled providers or invent complete totals. Pin this in Tasks 4 and 7.
5. A guest/account switch or slow settings refresh must not restore a disabled source, clear another account's choices or reset prepared chapter data. Pin this in Tasks 3, 10 and 12.

## Shared Contracts to Establish

Use these names consistently; put their JSDoc definitions in `shared/reading-contracts.js` and runtime parsers in the modules listed below.

| Contract                         | Exact shape / rule                                                                                                                                                                                                                                                      |
| -------------------------------- | ----------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| `Destination`, `IntegrationMode` | `'yoru' \| 'ara-ara'`; `'all' \| 'core' \| 'extensions'`                                                                                                                                                                                                                |
| `MediaRef`                       | Parsed `{id,kind}`; kind is `anime`, `manga`, or `extension-manga`. New IDs: `ext-manga-` followed by 32 lowercase hex characters, minted once by the store                                                                                                             |
| `EditionRef`                     | Parsed `{id,kind}` for existing remote IDs or `ext-chapter-` + 32 lowercase hex characters. Keep device-import parsing on its existing path                                                                                                                             |
| `SourceRef`                      | `{id,integration,upstreamSourceId,providerKey,language,classification,capabilities,bridgeInstance}`; integration is `core` or `suwayomi`; core IDs remain unchanged                                                                                                     |
| `Classification`                 | `{rating:'safe'\|'adult'\|'mixed'\|'unknown', provenance:{sourceField,value,checkedAt}}`; do not invent a safe classification                                                                                                                                           |
| `Capabilities`                   | Each of `popular,latest,search,details,chapters,pages,resolveLink` is `supported`, `unsupported`, or `unverified`; service availability is a separate state                                                                                                             |
| `UpstreamTitleRef`               | `{sourceId,upstreamKey,language}`; canonical provider identity, never only a local Suwayomi integer                                                                                                                                                                     |
| `UpstreamEditionRef`             | `{title:UpstreamTitleRef,upstreamKey}`; chapter number is metadata, not the permanent key                                                                                                                                                                               |
| `BridgeTitle`                    | `{sourceRef,upstreamRef:UpstreamTitleRef,localMangaId,classification,metadata}`; `metadata` contains normalized existing title-card fields without a public ID                                                                                                          |
| `BridgeEdition`                  | `{sourceRef,upstreamRef:UpstreamEditionRef,localMangaId,localChapterId,metadata}`; metadata preserves chapter number/volume/language/order and page count                                                                                                               |
| `BridgeFeed`, `BridgeManifest`   | `{items:BridgeTitle[],nextPage,hasMore,sourceState}`; `{edition:BridgeEdition,pages:number[]}` where page indices reveal no upstream URLs                                                                                                                               |
| `BinaryAsset`                    | `{body:Uint8Array,type,cached}`; only validated bounded image types are returned                                                                                                                                                                                        |
| `OperationContext`               | `{signal,deadlineAt,priority:'interactive'\|'discovery'}`; passed through bridge transport, queue and adapter methods                                                                                                                                                   |
| `SourceState`                    | `{sourceId,state:'ready'\|'empty'\|'unsupported'\|'unverified'\|'unavailable'\|'stale',status,retryAt,operation,reason}`; reason is a safe code such as `auth-required`, `access-challenge`, `rate-limited`, `offline`, `removed`, or null; no private URLs/credentials |
| `ReaderContext`                  | `{destination,integrationMode,userId,sessionHash,guestId,overrides,selectionFingerprint,language,signal}`; account identity comes only from the session                                                                                                                 |
| `ReadingMedia`                   | Existing media-card fields plus `{id,sourceRef,upstreamRef,classification,provenance,category,availableIntegrations}`; nullable unsupported rating/date fields stay null                                                                                                |
| `ReadingEdition`                 | Existing chapter DTO fields plus `{id,mediaId,sourceRef,upstreamRef,integration,volume,number,language,order,pageCount}`                                                                                                                                                |
| `FeedPage`                       | `{items:ReadingMedia[],nextCursor,hasMore,total:null,totalIsEstimate:true,sourceStates,selectionFingerprint}`; source-specific pages also carry their upstream next-page reference                                                                                      |
| `ReaderDb`                       | Async `get(sql,...values)`, `all(sql,...values)`, `run(sql,...values)`, `atomic(statements,guard?)`; statements are `{sql,values}`, guard is `{userId,sessionHash}`                                                                                                     |

`ReaderDeps` means `{db:ReaderDb,coreMedia:getMedia,bridge:ExtensionGateway,now,uuid}`. `ExtensionGateway` exposes `catalogs`, `browse`, `details`, `chapters`, `chapter`, `reader`, `cover`, `page`, `resolveLink`, accepting validated upstream references and `OperationContext`; no public opaque ID is resolved by guessing its upstream integer.

The generic gateway/adapter return types are: `catalogs -> {sources:SourceRef[],nextCursor}`, `browse -> BridgeFeed`, `details/resolveLink -> BridgeTitle`, `chapters -> {items:BridgeEdition[],nextPage,hasMore,sourceState}`, `chapter -> BridgeEdition`, `reader -> BridgeManifest`, `cover/page -> BinaryAsset`. Public APIs normalize/store these into `ReadingMedia` and `ReadingEdition` before serialization. Existing core adapter response shapes remain compatible; add explicit source metadata rather than changing their legacy URLs or chapter IDs. `ReadingEdition` retains the old chapter-list `pages` count alongside `pageCount`; the reader-manifest response retains its existing direct chapter shape with same-origin `{url}` page objects.
