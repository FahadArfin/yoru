## Controller rulings and implementation audit

These decisions were explicitly recorded by the controller during Tasks 1–13; they are not new policy invented by this document. Implementation evidence remains separate.

- Reuse the existing isolated `yoru-multisource` worktree on `codex/suwayomi-connection`; preserve repository/Sites identity. User authorization already covers commit/push, bridge recreation and publication. No repeat conversational approval is required.
- Independent tracks require disjoint ownership. Shared route/schema files and all Git index/stage/commit operations require root serialization. A dist validation window also freezes other agents' existing bundled/runtime source inputs. Unimported new modules, pure tests and documentation may proceed. Task 8's fix may validate an isolated archive of `7e85b35` plus its owned fixes; that artifact's evidence is distinct from final combined validation.
- Per-task reviews use immutable dispatch BASE..task HEAD scoped to explicitly owned paths when disjoint commits intervene; final whole-branch review covers all paths from `06cdd0a`.
- Canonical source/title/edition tuples are immutable. Local bindings are ephemeral and bridge-instance bound. Server-only bounded canonical/trusted-mapping proof requires both endpoints; no fuzzy identity/chapter/progress transfer. Unknown core chapters remain rejected without authoritative proof.
- Preference compatibility retains old overrides load/save/reset; new mode/revision operations are additive. Missing PATCH operation means legacy membership only. Unknown identity uses `credentials:omit` for context GET and reader reads, no guest projection POST, public defaults and no personal rating.
- Exact `readingChoices` use stored verified equivalences, retain distinct media/source identities and nullable unresolved core references. Across feed pages, additive updates append/upsert new exact choices even on terminal empty-item pages; never replace representative metadata or selected edition/progress.
- Existing editorial/core metadata shelves may remain in all/core and hide during extensions/context transitions. Unified feed state retains initially hidden core representatives so later native-choice updates can reveal one merged card. Metadata-only cards never claim readable matches; filters cannot overstate core availability.
- Whole-title unit 0 discussions may merge verified title equivalents. Chapters, including 0/decimal/specials, merge only through verified edition equivalence. Native chapter rooms require validated exact source + edition; numeric-only patches reject. Empty reader + unit 0 remains a title room; core integer behavior remains compatible. Comment parents require the same exact edition.
- Guest lease is at most 25 minutes from successful CAS POST; GET does not renew. Only matching known POST lease/revision/fingerprint can be reused. Expiry hides readiness and prevents transport; 409 refetches/reports without replay. All reader/cover/preload consumers preserve the full context and cancellation signal.
- A conflict or uncertain dispatched guest CAS timeout blocks passive synchronization for that destination in the active controller. Timer/focus/manual refresh may GET/reconcile/report only; an explicit mode/membership action clears its own destination, reset clears both. The barrier is not persisted across a new controller/page reload. Known successful lease renewal remains automatic; canceled queued projections never replay.
- Initialized Reader/Watch readiness uses a stable logical owner/destination/selection/confirmation key. Inventory observation generations continue to gate current history/actions but cannot remount a settled session. This is central context/readiness behavior, not a per-consumer latch or a relaxation of failed-proof history filtering.
- Tasks 9/11/12/13 may prepare independently against stable interfaces, but final integrated acceptance waits for their prerequisites. Task 10 owns the Shell stable-ref `getReaderSelection` seam; Task 12 exclusively owns `src/watch-views.js` activity context. Task 13 owns tools/docs/journeys and must wait for the final browser artifact.
- General tool search may add bounded optional opaque cursor, exact source ID and language arguments so later catalogs remain reachable. Current context mode/destination/owner remain authoritative; anime-category search rejects reading-only filters before HTTP. Continuation cannot be claimed from a first-page-only test.
- The positive-only public source grammar versus signed64 bridge grammar was ruled a binding-contract defect. Reuse the existing browser-safe `decimalSourceId` parser for canonical nonzero signed64 strings in tools and public gateway/aggregate/store validation; do not introduce a second canonicalization or schema.
